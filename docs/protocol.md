# Linux 实现与协议依据

本版本的静态协议基础是 [逆向报告](../analysis/逆向报告.md)，原始指令保存在 `analysis/evidence/driver-disasm.txt`（本地生成，见 [材料说明](../analysis/README.md)）。所有地址是原始主程序的 VA。

## 此次补充确认的字段

`0x408520` 将 `SELECT * FROM t_light_data WHERE profile = ? AND mode = ?` 的列映射到对象：mode 位于 `+0x0C`、brightness 位于 `+0x10`、speed 位于 `+0x14`、direction 位于 `+0x18`、colorful 位于 `+0x1C`、color_value 位于 `+0x24`。

`0x42B124..0x42B16A` 将这些对象字段编码为 Feature 业务块：

| 偏移 | 内容 |
| --- | --- |
| 0 | 模式编号 |
| 1..3 | COLORREF 低三字节，对应 R、G、B |
| 8 | colorful |
| 9 | brightness |
| 10 | speed |
| 11 | direction（当前固定为原厂初始值 0） |
| 14..15 | AA 55 |

模式为 0 时，上述参数位置保持零，尾标记仍保留。方向字段在该发送路径中存在，目前未暴露为 CLI/API 参数。无线版本由 `0x42B288..0x42B2C7` 编码，命令头为 `00 05 10 00`，参数位置后移 4 字节，尾标记在 18..19。

0.3.4 更正：此前误将偏移 9..11 解释为 mode、brightness、speed，使亮度实际改变速度、速度实际改变方向。`0x42B0A6` 传入的对象基址是 `ebp-0x88`，因此 `0x42B14A` 的 `[ebp-0x78]` 对应 brightness，而非 mode；后续 `[ebp-0x74]` 和 `[ebp-0x70]` 分别对应 speed、direction。无线分支使用同一布局。原厂 `0x42B398` 将 `0x5751C0` 的常量复制到对象 `+0x18`，其首个 DWORD 为 0，即初始方向。CLI、JSON API 与 GTK 共用修正后的编码器，参数名称与取值范围不变。

`0x4187C5` 使用 `key_index * 4` 写入键位槽，未减 1。普通映射为 `[02, modifier_mask, key_usage, 00]`。`0x451B40` 将 E0..E7 映射为 1、2、4、8、16、32、64、128。默认槽保留零，与原厂先清零缓冲区、只编码覆盖项的流程一致。

有线普通层选择 `04 11`，Fn 层选择 `04 27`。两者选择包偏移 8 都为 9；576 字节表发送为 9 个块。原厂 `0x418DAD` 之后的收尾顺序为带确认的 `04 02`、带确认的 `04 F0`。灯光流程中的 `04 F0` 则不请求同样确认。

无线键位来自 `0x4190A6`：普通层命令 10、Fn 层命令 12，发送 21 个块，前 20 块长度 28，末块有效长度 16；每个缓存仍复制 28 字节。末块缓存中超过 576 字节表末尾的数据被清零，但仍参与短报文校验。

## Linux HID 封装

Linux 接口以本机 `/usr/include/linux/hidraw.h` 与 [内核 hidraw 文档](https://kernel.org/doc/html/latest/hid/hidraw.html) 为依据。

发送 Feature 时提供 65 字节，首字节 0，随后 64 字节业务数据。读取时考虑无 Report ID 设备的两类内核/驱动表现：返回 64 字节业务数据，或返回以 0 开头的 65 字节 API 缓冲区。它们归一化为 64 字节业务数据后检查偏移 3 的状态。其他长度或非零首 Report ID 的 65 字节响应被拒绝。

无线 Output 采用 33 字节 API 缓冲区，首字节 0，随后 32 字节实际报告。读取无 Report ID 的 Input 通常直接返回 32 字节，无需盲目移除首字节。原厂逻辑的短报文校验是在覆盖校验字段前累加；本实现所有 33 字节缓冲区初始化为零，未发送的源缓冲区尾部也为零，因而校验可以准确计算为前 32 字节的低八位累加。

运行期间读取到的本机 2.4G 接收器身份为 `05AC:024F`，接口 3 的 Usage Page 为 FF60，Input/Output 各 32 字节；接口 4 同为 FF60，但 Input/Output 各 64 字节。此观察仅为 sysfs 只读检查。工具扫描全部 HID 条目，按总线、VID/PID 及产品型号过滤，再按 USB 物理设备父节点合并。用户按扫描到的硬件名或 ID 选择目标，程序据报告能力识别通道，不使用固定接口编号或 hidraw 编号。其他厂商、其他型号以及身份无法读取的条目不出现在结果中。

## 校验边界

离线测试验证了编码、调用顺序、异常处理及内核 API 参数。测试中的黄金包由原厂指令推导，不是 USB 抓包。随后在宿主环境授权配置节点后进行了真实写入：2.4G 灯光已收到响应且用户确认变化；按键映射的各次物理验证结果见 [实机测试记录](../analysis/hardware-tests/results.md)。短报文回显只证明响应匹配，不能证明实际按键输出改变。

用户提供的 2024-10-16 版说明书明确记载 `Fn+Tab` 可以屏蔽或打开驱动自定义按键指令。映射未生效时需要检查该开关；当前没有实现读取其状态的协议。旧版硬件的映射继续以本项目原厂 EXE 及 XML 为依据，不使用网页驱动的键位表。

完整层映射会清除所选层中未列出的自定义项。当前没有读回备份、合并设备状态或自动回滚功能；配置 JSON 是用户的完整层定义。有线与 2.4G 下的持久化效果、特殊键源的映射行为和不同硬件批次兼容性，应继续以实机验证。
