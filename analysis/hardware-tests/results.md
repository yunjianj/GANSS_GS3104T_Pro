## 未生效原因

此前 Pause→B、A→B、初始化探测后 A→B、整层 A→B 均收到回显，但用户观察到按键仍保持默认行为。用户提供的 2024-10-16 版说明书“基础功能组合键”记载：**Fn+Tab：屏蔽或打开驱动自定义按键指令**。

重新发送单键 A→B 后，用户按 Fn+Tab，A 即输出 b/B；随后不增加任何提交命令，原来的 21 块整层路径同样生效。因此这些失败不能用于否定旧版键位索引或证明缺少提交命令。工具已增加 Fn+Tab 排查提示，未实现读取或自动改变该开关状态。

## 测试结束状态与边界

普通层已恢复默认，并由用户确认 A 输出 a/A；Fn+Tab 保持用户启用映射后的状态。灯光保持测试时的橙色配置。没有发送恢复出厂或固件升级指令。

本次验证覆盖 2.4G 灯光、普通键单键映射、普通层整层映射及恢复。Fn 层、修饰组合键、Pause 等专用键、断电保存、有线通道尚未获得物理效果验证。JSONL 记录的是 Linux 工具实际发送和接收的数据，不是原厂软件 USB 抓包；短报文回显本身不等于物理效果验证。

## 有线扫描修复（0.3.1）

用户切换有线后，系统实际 HID_NAME 为 `HFD GS3104T PRO`，USB 产品字段为 `GS3104T PRO`，VID/PID 仍为 `05AC:024F`。原扫描器只匹配不带 HFD 的型号，导致所有接口被过滤。

修复为接受这一已观察到的精确型号变体，设备显示名和操作目标保留原始 `HFD GS3104T PRO`。仍过滤其他型号和厂商，不按接口号选择设备。主机观察到三个接口；配置接口 Usage Page FF13，无 Report ID，Input/Output/Feature 均为 64 字节。

修复后主机扫描只显示一台目标键盘，状态 ready；已只读打开配置节点并通过 ioctl 型号和描述符复核。固件 prepare 同样可按原始硬件名完成只读预检。此验证未发送灯光、映射、进入 ISP、擦除、刷写或复位指令，因此不增加有线配置实际效果或固件更新的验证结论。原始结果见本地 `local/hardware-tests/wired-scan.json`。

## 有线 ISP 只查询诊断（2026-11-08）

用户授权一次进入 ISP、查询和退出。实机在原 `05AC:024F` / `HFD GS3104T PRO` 的原通道响应 `01 aa 55 00 fa fa fa fa 20 03 00 00 00 00 5a 5a 1e 00`（余字节零）。进入时未发生 USB 断连。初版诊断错误要求 `20 05` 而超时，原始记录见 `isp-probe-result.json`。随后只发送退出命令 07，系统日志确认重新枚举，用户确认恢复正常输入。未执行擦除、Code Option 修改或固件写入。

用户确认此官方 EXE 在 Windows 上可成功刷写。同一回复不能只依通用表名称解释为实际 SN32F248B、64 KiB 或官方固件不兼容。后端已更正这类诊断结论和握手匹配；更新后的完整诊断流程仅完成离线回归验证。本次不重复进入 ISP 或尝试刷写。
